Why is my Magento product not showing on the website?

By Gaurav Harsh, Magento developer · 21 November 2026 · Magento Open Source and Adobe Commerce 2.4

Short answer: a Magento 2 product only shows when, for that store view, it's enabled, visible, assigned to the website, in stock, in a category (for category pages), indexed with a price, and the cache has been refreshed. One failing check is enough to hide it.

The checklist, in the admin

Open Catalog › Products, open the product, and switch the Scope (top left) to the store view where it's missing. Values can be different per store view, which is the most common surprise.

  1. Enable Product = Yes. Check it at store view scope too: a store view can override the default and disable the product only there.
  2. Visibility. "Catalog, Search" shows it everywhere. "Catalog" means category pages only, "Search" means search results only. "Not Visible Individually" hides it on its own; that's normal for the variants of a configurable product.
  3. Product in Websites. The website that the store view belongs to must be ticked.
  4. Stock. Quantity above 0 and Stock Status "In Stock". If you use several sources, check the Salable Quantity column on the product grid. Out-of-stock products are hidden unless Stores › Configuration › Catalog › Inventory › Stock Options › Display Out of Stock Products is Yes.
  5. Categories. Needed to appear on a category page (not for search or the product's own URL). The category itself must be enabled.
  6. Configurable products: at least one variant must be enabled, in stock and assigned to the same website.
  7. Price. Category pages only list products that have a price in the price index for that website. A missing price, or a price index that hasn't run, hides the product.
  8. Indexers. Run bin/magento indexer:status. "Reindex required", or a growing backlog in "Update by Schedule" mode, means your changes haven't reached the storefront yet. Check that cron is running.
  9. Cache. Flush it under System › Cache Management, and in Varnish or your CDN if you use one.

Adobe Commerce only: B2B shared catalogs and category permissions can hide products from some customer groups, and a scheduled update can change a product's status at a set time.

Check most of it at once, with one query

For you or your developer. Change the SKU and the store view code (find it under Stores › All Stores), then run it.

These queries only read data. Run them on a copy of your database if you can, or ask your developer to. If your tables have a prefix (set in app/etc/env.php), add it to each table name.

Magento Open Source

SET @sku   = 'ABC-123';   -- the product's SKU
SET @store = 'default';   -- the store view code (Stores > All Stores)

SELECT
  e.sku,
  e.type_id                                  AS type,
  COALESCE(st_store.value, st_def.value)     AS status,
  COALESCE(vis_store.value, vis_def.value)   AS visibility,
  EXISTS (SELECT 1 FROM catalog_product_website w
          WHERE w.product_id = e.entity_id AND w.website_id = s.website_id) AS in_website,
  (SELECT COUNT(*) FROM catalog_category_product c
   WHERE c.product_id = e.entity_id)          AS categories,
  si.is_in_stock                             AS in_stock,
  si.qty,
  EXISTS (SELECT 1 FROM catalog_product_index_price p
          WHERE p.entity_id = e.entity_id AND p.website_id = s.website_id) AS has_price_index
FROM catalog_product_entity e
JOIN store s ON s.code = @store
JOIN eav_entity_type t ON t.entity_type_code = 'catalog_product'
JOIN eav_attribute a_st  ON a_st.entity_type_id  = t.entity_type_id AND a_st.attribute_code  = 'status'
JOIN eav_attribute a_vis ON a_vis.entity_type_id = t.entity_type_id AND a_vis.attribute_code = 'visibility'
LEFT JOIN catalog_product_entity_int st_def    ON st_def.entity_id    = e.entity_id AND st_def.attribute_id    = a_st.attribute_id  AND st_def.store_id    = 0
LEFT JOIN catalog_product_entity_int st_store  ON st_store.entity_id  = e.entity_id AND st_store.attribute_id  = a_st.attribute_id  AND st_store.store_id  = s.store_id
LEFT JOIN catalog_product_entity_int vis_def   ON vis_def.entity_id   = e.entity_id AND vis_def.attribute_id   = a_vis.attribute_id AND vis_def.store_id   = 0
LEFT JOIN catalog_product_entity_int vis_store ON vis_store.entity_id = e.entity_id AND vis_store.attribute_id = a_vis.attribute_id AND vis_store.store_id = s.store_id
LEFT JOIN cataloginventory_stock_item si ON si.product_id = e.entity_id AND si.stock_id = 1
WHERE e.sku = @sku;

Adobe Commerce

On Adobe Commerce, product attributes are stored per version (for scheduled updates) and linked by row_id instead of entity_id. Use this version there:

SET @sku   = 'ABC-123';   -- the product's SKU
SET @store = 'default';   -- the store view code (Stores > All Stores)

SELECT
  e.sku,
  e.type_id                                  AS type,
  COALESCE(st_store.value, st_def.value)     AS status,
  COALESCE(vis_store.value, vis_def.value)   AS visibility,
  EXISTS (SELECT 1 FROM catalog_product_website w
          WHERE w.product_id = e.entity_id AND w.website_id = s.website_id) AS in_website,
  (SELECT COUNT(*) FROM catalog_category_product c
   WHERE c.product_id = e.entity_id)          AS categories,
  si.is_in_stock                             AS in_stock,
  si.qty,
  EXISTS (SELECT 1 FROM catalog_product_index_price p
          WHERE p.entity_id = e.entity_id AND p.website_id = s.website_id) AS has_price_index
FROM catalog_product_entity e
JOIN store s ON s.code = @store
JOIN eav_entity_type t ON t.entity_type_code = 'catalog_product'
JOIN eav_attribute a_st  ON a_st.entity_type_id  = t.entity_type_id AND a_st.attribute_code  = 'status'
JOIN eav_attribute a_vis ON a_vis.entity_type_id = t.entity_type_id AND a_vis.attribute_code = 'visibility'
LEFT JOIN catalog_product_entity_int st_def    ON st_def.row_id       = e.row_id AND st_def.attribute_id    = a_st.attribute_id  AND st_def.store_id    = 0
LEFT JOIN catalog_product_entity_int st_store  ON st_store.row_id     = e.row_id AND st_store.attribute_id  = a_st.attribute_id  AND st_store.store_id  = s.store_id
LEFT JOIN catalog_product_entity_int vis_def   ON vis_def.row_id      = e.row_id AND vis_def.attribute_id   = a_vis.attribute_id AND vis_def.store_id   = 0
LEFT JOIN catalog_product_entity_int vis_store ON vis_store.row_id    = e.row_id AND vis_store.attribute_id = a_vis.attribute_id AND vis_store.store_id = s.store_id
LEFT JOIN cataloginventory_stock_item si ON si.product_id = e.entity_id AND si.stock_id = 1
WHERE e.sku = @sku
  AND e.created_in <= UNIX_TIMESTAMP() AND e.updated_in > UNIX_TIMESTAMP();  -- the current version of the product

How to read the result

ColumnWhat you want to see
status1 (enabled). 2 means disabled, either everywhere or just in this store view.
visibility4 (Catalog, Search), 2 (Catalog) or 3 (Search). 1 means Not Visible Individually.
in_website1. 0 means the product isn't assigned to this store's website.
categories1 or more, if it should be on a category page.
in_stock1, unless "Display Out of Stock Products" is on. For a configurable product, qty is 0 and that's normal: the stock is on its variants.
has_price_index1. 0 means it won't appear on category pages: check the price and reindex.

If every column looks right, the cause is usually the indexers, the cache, or (on Adobe Commerce) customer-group permissions.
