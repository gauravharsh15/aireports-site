Magento 2 sales_order_grid table

By Gaurav Harsh, Magento developer · 21 November 2026 · Checked against Magento Open Source and Adobe Commerce 2.4.8

A flattened copy of each order that powers Sales › Orders in the admin. It's built from sales_order and its addresses and payment.

Key columns

ColumnWhat it means
entity_idThe same ID as sales_order.entity_id.
increment_idThe order number.
statusThe order status code.
store_id / store_nameWhere the order was placed.
customer_email / customer_nameCopied from the order.
billing_name / shipping_nameNames from the order's addresses.
base_grand_total / grand_totalOrder totals.
payment_methodPayment method code.

Good to know

  • It's a copy, not the source. If asynchronous grid indexing is on (setting dev/grid/async_indexing), new orders appear in the grid only after cron runs.
  • An order missing from the admin grid but present in sales_order usually means cron isn't running or the grid needs reindexing.

Example: Orders that are missing from the admin order grid

Works on Magento Open Source and Adobe Commerce.

SELECT o.entity_id, o.increment_id, o.created_at
FROM sales_order o
LEFT JOIN sales_order_grid g ON g.entity_id = o.entity_id
WHERE g.entity_id IS NULL
ORDER BY o.entity_id DESC;

Tested on Magento Open Source and Adobe Commerce 2.4.8. Read-only. If your tables have a prefix, add it to each table name.
