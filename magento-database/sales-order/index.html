Magento 2 sales_order table

By Gaurav Harsh, Magento developer · 21 November 2026 · Checked against Magento Open Source and Adobe Commerce 2.4.8

One row per order: its number, state and status, customer, store view, totals and currencies. Every other sales table points back to it.

Key columns

ColumnWhat it means
entity_idInternal order ID. Other sales tables link to it, e.g. sales_order_item.order_id.
increment_idThe order number shown in the admin and in emails, such as 000000123.
stateMagento's fixed workflow stage: new, pending_payment, processing, complete, closed, canceled, holded or payment_review.
statusThe status code shown to people. Each state can have several statuses, including your own custom ones.
store_idThe store view the order was placed in.
customer_idThe customer account, or NULL for guest orders (then customer_is_guest is 1).
grand_total / base_grand_totalThe order total in the order's currency / in your base currency.
discount_amountThe order's discount, stored as a negative number.
created_atWhen the order was placed, stored in UTC.

Good to know

  • Columns starting with base_ are in your base currency; the others are in the currency the customer paid in.
  • "On Hold" is stored as holded. Query status codes, not the labels you see in the admin.
  • On Adobe Commerce this table has many more columns, for gift cards, store credit, reward points and gift wrapping (full list below).

Example: Orders and revenue per status, last 30 days

Works on Magento Open Source and Adobe Commerce.

SELECT status, COUNT(*) AS orders, ROUND(SUM(base_grand_total), 2) AS revenue
FROM sales_order
WHERE created_at >= NOW() - INTERVAL 30 DAY
GROUP BY status
ORDER BY orders DESC;

Tested on Magento Open Source and Adobe Commerce 2.4.8. Read-only. If your tables have a prefix, add it to each table name.

  • customer_id → customer_entity.entity_id
  • store_id → store.store_id
