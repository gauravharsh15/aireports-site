Why are Magento order confirmation emails not being sent?

By Gaurav Harsh, Magento developer · 26 November 2026 · Magento Open Source and Adobe Commerce 2.4

Short answer: Each order records whether an email should be sent and whether it was. With asynchronous sending on, emails only go out when cron runs. With email communications disabled, nothing goes out at all.

Check it step by step

These queries only read data. Run them on a copy of your database if you can, or ask your developer to. If your tables have a prefix (set in app/etc/env.php), add it to each table name.

1. Orders waiting for their email

Works on Magento Open Source and Adobe Commerce:

SELECT increment_id, created_at, send_email, email_sent
FROM sales_order
WHERE created_at >= NOW() - INTERVAL 2 DAY
  AND (email_sent IS NULL OR email_sent = 0)
ORDER BY created_at DESC;

send_email = 1 with email_sent empty means the email is queued but hasn't gone.

2. The settings that decide it

Works on Magento Open Source and Adobe Commerce:

SELECT path, scope, scope_id, value
FROM core_config_data
WHERE path IN ('sales_email/general/async_sending', 'system/smtp/disable', 'sales_email/order/enabled');

async_sending = 1 means cron sends them. system/smtp/disable = 1 stops every email. No row means the default is used.

How to fix it

  • If emails are queued, check cron: the sales_send_order_emails job sends them. See cron not running.
  • Stores › Configuration › Advanced › System › Mail Sending Settings › Disable Email Communications must be No.
  • If emails leave Magento but never arrive, the problem is the mail server or SPF/DKIM, not Magento.
