Which product attributes are overridden per store view?

By Gaurav Harsh, Magento developer · 26 November 2026 · Magento Open Source and Adobe Commerce 2.4

Short answer: A value saved at store-view level wins over the default in that store view. Overrides are the usual reason a product looks different in one language or country. Count them per attribute, then look at one SKU.

Check it step by step

These queries only read data. Run them on a copy of your database if you can, or ask your developer to. If your tables have a prefix (set in app/etc/env.php), add it to each table name.

1. Overrides per attribute and store view

Works on Magento Open Source and Adobe Commerce:

SELECT a.attribute_code, x.store_id, COUNT(*) AS overridden_values
FROM (
  SELECT attribute_id, store_id FROM catalog_product_entity_varchar  WHERE store_id > 0
  UNION ALL SELECT attribute_id, store_id FROM catalog_product_entity_int      WHERE store_id > 0
  UNION ALL SELECT attribute_id, store_id FROM catalog_product_entity_text     WHERE store_id > 0
  UNION ALL SELECT attribute_id, store_id FROM catalog_product_entity_decimal  WHERE store_id > 0
  UNION ALL SELECT attribute_id, store_id FROM catalog_product_entity_datetime WHERE store_id > 0
) x
JOIN eav_attribute a ON a.attribute_id = x.attribute_id
GROUP BY a.attribute_code, x.store_id
ORDER BY overridden_values DESC;

Names and descriptions are often translated on purpose. Status, visibility, price and URL key overrides are usually accidents.

2. Every override on one product

Magento Open Source

SET @sku = 'ABC-123';  -- your SKU
SELECT a.attribute_code, v.store_id, v.value
FROM catalog_product_entity e
JOIN (
  SELECT entity_id, attribute_id, store_id, value FROM catalog_product_entity_varchar WHERE store_id > 0
  UNION ALL SELECT entity_id, attribute_id, store_id, CAST(value AS CHAR) FROM catalog_product_entity_int WHERE store_id > 0
  UNION ALL SELECT entity_id, attribute_id, store_id, LEFT(value, 80) FROM catalog_product_entity_text WHERE store_id > 0
  UNION ALL SELECT entity_id, attribute_id, store_id, CAST(value AS CHAR) FROM catalog_product_entity_decimal WHERE store_id > 0
) v ON v.entity_id = e.entity_id
JOIN eav_attribute a ON a.attribute_id = v.attribute_id
WHERE e.sku = @sku
ORDER BY a.attribute_code, v.store_id;

Adobe Commerce

Product, category, rule and CMS values are stored per version and joined on row_id (why):

SET @sku = 'ABC-123';  -- your SKU
SELECT a.attribute_code, v.store_id, v.value
FROM catalog_product_entity e
JOIN (
  SELECT row_id, attribute_id, store_id, value FROM catalog_product_entity_varchar WHERE store_id > 0
  UNION ALL SELECT row_id, attribute_id, store_id, CAST(value AS CHAR) FROM catalog_product_entity_int WHERE store_id > 0
  UNION ALL SELECT row_id, attribute_id, store_id, LEFT(value, 80) FROM catalog_product_entity_text WHERE store_id > 0
  UNION ALL SELECT row_id, attribute_id, store_id, CAST(value AS CHAR) FROM catalog_product_entity_decimal WHERE store_id > 0
) v ON v.row_id = e.row_id
JOIN eav_attribute a ON a.attribute_id = v.attribute_id
WHERE e.sku = @sku
  AND e.created_in <= UNIX_TIMESTAMP() AND e.updated_in > UNIX_TIMESTAMP()
ORDER BY a.attribute_code, v.store_id;

How to fix it

  • Open the product, switch the scope to the store view and tick Use Default Value on the field to remove an override.
  • Mass updates in the admin (Update attributes) at store-view scope create overrides for every selected product.
